# 为什么有 API 会更好

## 不用 API 的版本

系统可以自动抓到：

```text
Doctoral Researcher in Extended Reality
Deadline: 20 August 2026
University: XXX
```

但它很难可靠判断：

- 这个岗位究竟是 Human-Centred XR，还是 computer vision；
- 是否与你的 spatial cognition 研究有关；
- 是 exact fit 还是 adjacent fit；
- 你缺少哪些资格；
- 是否值得投入两三天准备申请；
- 一个基金项目是否可能产生未来招聘。

这些任务需要理解上下文，而不是单纯匹配关键词。

## 使用 API 的版本

API 能阅读职位正文后，输出结构化结果：

```yaml
fit_score: 84
fit_type: adjacent-methodological-fit
fit_level: High

why_match:
  - Human-centred immersive systems
  - Experimental user studies
  - Collaborative interaction
  - Behavioural evaluation

missing_qualifications:
  - Python
  - Mixed-effects modelling
  - Eye tracking

recommendation: apply
confidence: 0.86
```

这才是真正的“研究情报系统”，而不是职位网页收藏夹。

# API 不应该做什么

不要让模型负责判断客观事实，例如：

- 截止日期；
- 工资；
- 职位是否仍开放；
- 学校名称；
- 官方来源；
- 合同年限。

这些字段应由 Python 从官方页面直接提取和保存。

API 只负责较高层判断：

- 研究主题分类；
- 研究方法匹配；
- 技能提取与标准化；
- 对你个人的适配度；
- 风险分析；
- 中文摘要。

否则模型一旦误读日期，就可能让你错过申请。

---

# 我建议使用“两阶段 AI 分析”

不要每抓到一个页面就直接发送完整内容给昂贵模型。

## 第一阶段：便宜模型做快速筛选

任务包括：

- 这是不是研究岗位；
- 是否仍然开放；
- 是否明显属于排除方向；
- 是否可能达到 70% 匹配；
- 提取基础技能关键词。

输出只需要：

```json
{
  "relevant": true,
  "category": "human-centred-xr",
  "possible_fit": 0.78
}
```

明显不相关的岗位在这里结束。

## 第二阶段：较强模型做深度分析

只有通过第一阶段的岗位才分析：

- exact fit 或 adjacent fit；
- 你的优势与缺口；
- practical action；
- risks；
- 是否值得申请；
- 未来招聘信号。

这样可以显著控制成本，也减少无关输出。

# API 成本实际会不会高

如果设计正确，通常不会高。

假设每天：

- 抓取 100 个网页；
- Python 和关键词规则淘汰 85 个；
- 便宜模型筛选 15 个；
- 只有 2-5 个交给较强模型完整分析。

真正进入深度分析的内容很少。

你不应该把整张 HTML 页面发送给模型，而应先用 Python 清理：

- 导航栏；
- Cookie 信息；
- 页脚；
- 重复菜单；
- JavaScript；
- 无关职位；
- 图片标签。

只保留职位正文。

这样成本可能非常低。具体金额取决于你所使用的 API 供应商、模型及输入输出价格，不能仅凭“便宜 API”判断。

# 你的便宜 API 是否适合

需要检查六件事。

## 1. 是否支持结构化 JSON 输出

最好能要求模型严格输出 JSON Schema。OpenAI 当前推荐使用 Responses API，并支持结构化输出工作流；ChatGPT 与 API 仍为分开计费。([OpenAI Platform](https://platform.openai.com/docs/api-reference/run-steps/getRunStep?utm_source=chatgpt.com))

若 API 经常输出损坏的 JSON，自动化系统会很难维护。

## 2. 是否真的支持 GitHub Actions

API 必须可以通过：

```text
HTTPS request + API key
```

调用，而不是只能在某个聊天网页中使用。

## 3. 是否稳定

便宜 API 常见问题包括：

- 模型名称突然变化；
- 限速；
- 请求偶尔无响应；
- 输出被截断；
- 服务突然停止；
- 宣称是某模型，但无法验证。

## 4. 数据隐私条款

职位内容本身通常是公开资料，但以后系统可能包含：

- 你的 CV；
- 申请策略；
- 教授联系记录；
- 未公开论文摘要；
- 个人评估。

不要把这些全部发送给来源不明的 API。

## 5. 是否允许商业或自动化使用

需要查看服务条款，不要仅根据价格判断。

## 6. 是否兼容 OpenAI SDK

最好支持类似：

```python
client = OpenAI(
    api_key=...,
    base_url=...
)
```

这样以后更换供应商，只修改配置，不需要重写系统。

# 最重要的质量控制

## 1. 所有 AI 判断都保存置信度

```yaml

```

低于某个阈值就进入：

```text

```

```yaml

```


系统应分别保存：
